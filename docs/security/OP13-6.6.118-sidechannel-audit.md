## Applied to workflow

- Explicitly require `CONFIG_MITIGATE_SPECTRE_BRANCH_HISTORY=y`.
- After `gki_defconfig`, fail the build if any of the following is missing: `CONFIG_MITIGATE_SPECTRE_BRANCH_HISTORY`, `CONFIG_ARM64_SW_TTBR0_PAN`, `CONFIG_BPF_JIT_ALWAYS_ON`, `CONFIG_RANDOMIZE_BASE`, `CONFIG_SHADOW_CALL_STACK`, `CONFIG_CFI_CLANG`, `CONFIG_HARDENED_USERCOPY`.
- Fail the build if crucial Spectre-BHB detection or eBPF speculative-path verification sources are absent.
- These are **security regression checks**, not claims that a fresh CPU vulnerability was fixed and not proof of runtime mitigation.

## Not yet merged; requires separate compatibility work

1. **Zero-width Unicode / FUSE-BPF directory-visibility leak.** Inconsistent Unicode default-ignorable handling between MediaProvider FUSE and F2FS/EXT4 casefold is mainly a **userspace MediaProvider** issue, with a separate FUSE-BPF dentry revalidation gap. FuseFixer is an Xposed-level workaround, not a direct kernel patch. Its author proposed Android kernel review **3943780** for revalidating backing-inode lookups, but it remains described as unmerged; the patch has not been adapted or validated on this vendor 6.6 source. Do not claim the leak fixed by the AK3.
2. **Newer eBPF Spectre-v1 speculation-barrier series (2025)** modifies verifier and JIT behavior across multiple commits. It is not a trivial isolated stable fix; no blind cherry-pick until the exact upstream merged/stable series and vendor BPF ABI are reviewed.
3. **2026-09 Android kernel bulletins (NFC / pKVM / HID / TIPC).** These are serious security items but not necessarily CPU side channels; identify affected device components and exact upstream commits before backporting. Do not mark the AK3 as having a new Android security patch level from only these checks.
4. **Kernel BTI / other hardening switches.** The vendor baseline has `CONFIG_ARM64_BTI_KERNEL` disabled. Enabling it without Clang/driver/KMI validation may break out-of-tree modules; not changed here.

## On-device validation before claiming security coverage

- Keep boot image backup and record current stock and custom kernel/firmware versions.
- With the new kernel booted and before using CPU spoofing, inspect `/sys/devices/system/cpu/vulnerabilities/*` (especially `spectre_v2`), `/proc/cmdline` and `/proc/config.gz` if exported.
- Verify none of the boot arguments disables speculation mitigations (e.g. `mitigations=off`, `nospectre_bhb`, `nospectre_v2`).
- Run Android CTS/VTS where available, plus storage/MediaProvider/FUSE-BPF regression tests, if applying any future zero-width/FUSE patch.
- Ensure the current SukiSU CPU identity spoofing extension is **not** changing the reported CPU features during mitigation verification.
